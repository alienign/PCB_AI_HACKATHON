# PCB Vision AI — AI-помощник для визуальной диагностики печатных плат

**PCB Vision AI** — прототип настольного приложения для специалистов по ремонту электроники. По фотографии печатной платы система обнаруживает предполагаемые **визуальные дефекты**, выделяет их на изображении и помогает мастеру обратить внимание на подозрительные области.

> **Важно:** это инструмент предварительного визуального контроля, а не замена электрическим измерениям, диагностике цепей или заключению инженера о причине неисправности.

## Возможности MVP

- Загрузка фотографий PCB в формате JPEG/PNG для анализа.
- Обнаружение визуальных дефектов с помощью модели YOLOv8m.
- Отображение прямоугольников обнаружений (**bbox**), типа дефекта и уверенности модели (**confidence**).
- Список дефектов с номерами, соответствующими номерам рамок на изображении.
- Возможность показывать и скрывать отдельные обнаружения через флажки без изменения их исходной нумерации.
- Просмотр истории анализов и повторное открытие сохранённых результатов.
- Обработка ошибок загрузки и сетевого взаимодействия в Qt-интерфейсе.

## Архитектура

```text
Qt Widgets / C++ (PCBVisionAI)
        │ HTTP(S)
        ▼
FastAPI (Python 3.11)
        ├── YOLOv8m — анализ изображения
        ├── PostgreSQL — запросы, результаты и история
        └── файловое хранилище — загруженные изображения
```

Qt-клиент не обращается к базе данных или модели напрямую: все операции выполняются через API. Серверную часть можно запускать в Docker; во время командной демонстрации Qt-клиент подключался к ней через ngrok.

## Как запустить

### Backend

Для серверной части нужны Docker Compose **или** локальное окружение Python/PostgreSQL и проверенные веса ML-модели. Веса `best.pt` не хранятся в Git.

Инструкции по конфигурации, миграциям, API и локальному запуску: **[backend/README.md](backend/README.md)**. При использовании Docker дополнительно сверяйте настройки с [`docker-compose.yml`](docker-compose.yml) и [`.env.example`](.env.example); секреты не публикуйте.

> Примечание: разделы `backend/README.md` с историческими коммитами и результатами старых тестов могут быть неактуальны для текущего релиза. Актуальное состояние интеграции отражено в GitHub `main`.

### Qt-клиент (Windows)

Исходный проект находится в [`frontend/PCBVisionAI`](frontend/PCBVisionAI). Для сборки необходимы совместимые версии Qt, компилятора C++ и CMake. Откройте `CMakeLists.txt` в Qt Creator или соберите проект через CMake с установленным Qt.

Сборка для распространения на компьютерах **без Qt Creator** требует включения Qt-библиотек (обычно с помощью `windeployqt`). Готовый переносимый `.exe`/установщик пока **не заявлен** как опубликованный в репозитории.

Для работы приложения нужен доступный URL Backend. Если адрес сервера или ngrok меняется, настройте клиент в соответствии с реализацией `frontend/PCBVisionAI/apiclient.cpp` перед демонстрацией.

## Основные маршруты API

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `GET` | `/health` | Доступность FastAPI |
| `POST` | `/images` | Загрузить изображение (`multipart/form-data`, поле `file`) |
| `GET` | `/images/{image_id}` | Получить исходное изображение |
| `POST` | `/analysis-requests` | Создать запрос анализа по `image_id` |
| `GET` | `/analysis-requests/{request_id}` | Получить статус и обнаружения |
| `GET` | `/analysis-requests` | Получить историю анализов |

Подробности форматов и ошибок — в [документации Backend](backend/README.md). OpenAPI доступен по `/docs` при запущенном сервере.

## Демонстрация на хакатоне

В принятом командой варианте **Qt-приложение запускается на Windows-ноутбуке**, а **Backend, YOLOv8 и PostgreSQL — на отдельном ноутбуке с Docker**. Клиент обращается к серверу через ngrok. Для показа необходимо заранее проверить доступность сервера, актуальность адреса и наличие проверенных демонстрационных изображений.

Сценарий показа: **выбрать фотографию платы → запустить анализ → посмотреть найденные дефекты и confidence → скрыть/показать рамки → открыть результат из истории**.

## Ограничения

- Модель ищет **визуальные** признаки дефектов и не определяет электрическую причину поломки.
- Качество на новых типах плат и фотографиях зависит от данных, освещения, качества снимка и доменного сдвига; отдельные показатели точности здесь не заявляются.
- MVP ориентирован на демонстрационный сценарий и не включает полноценную пользовательскую авторизацию.
- Работа через внешний сервер/ngrok зависит от подключения к сети и доступности Backend.
